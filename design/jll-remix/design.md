## 1. 범위와 근거

이 문서는 실제 H 코드에서 확인한 표현을 정리한 SPS 작업용 기준이다. JLL 공식 브랜드 가이드가 아니다. 사용자가 JLL B안을 복사한 H에 여러 시안의 요소를 재조합하겠다고 요청했으며, 이번에 헤더 검색·국가/언어 표시 제거와 연한 붉은색 문의 버튼을 선택했다.

읽은 구현: `jll-remix.html`, `jll-remix.css`, `jll-remix.js`, `jll-remix-motion.css`, `jll-remix-motion.js`. 연결된 소개 페이지 `jll-remix-about.*`는 본문에 별도 스타일을 사용하며, 헤더는 `jll-remix-header.js`·`.css`를 통해 H 메인과 공유한다. 최초 `DESIGN-mastercard.md`와 B·C·G 등 다른 시안은 보존한다.

이 문서는 색·타이포·모양·컴포넌트를 다룬다. 무엇을 먼저 보여줄지, 정보의 근거와 상태를 어떻게 설명할지는 `CONCEPT.md`에서 판단한다. 해당 문서의 F·G 적용 기록을 H의 현재 구현으로 간주하지 않는다. 두 문서가 충돌하면 충돌 항목·변경 이유·영향 범위를 기록하고 선택한 시안에만 적용한다.

## 2. 표현 방향

넓은 공간 사진, 흰 바탕, 잉크색 제목, 직선 중심의 구획을 사용한다. 붉은색은 다음 행동·중요한 전환 지점을 표시한다. 공통 헤더의 현재 위치 밑줄은 기존 Red, 호버·키보드 초점·펼침은 Line의 연한 회색으로 구분한다. 현재 위치는 호버 중에도 Red를 유지한다. 연한 색상 면은 설명의 맥락을 구분한다. 다른 시안을 가져와도 역할이 같은 버튼과 글자는 이 기준에 맞춘다.

## 3. 색상

색상 값의 실행 원본은 `jll-remix-tokens.css`다. 메인 스타일이 이를 가져오며, 시각화 페이지도 같은 스타일을 불러온다.

- 색상을 지정할 때는 파운데이션의 기존 색상 토큰과 현재 적용값에서 역할에 맞는 색을 우선 선택한다. 같은 역할의 색을 재사용해 공통 컴포넌트의 일관성과 편집 연결을 유지한다.
- 기존 색상으로 목적을 충족하기 어려우면, 새 색을 적용하기 전에 필요한 이유와 후보를 사용자에게 묻고 선택한 색을 반영한다. 임의로 새 색상을 추가하지 않는다. (사용자 지정 원칙, 2026-10-07)

| 토큰 | 현재 값 | 사용 역할 |
|---|---|---|
| `--ink` | `#10252B` | 제목·본문·진한 버튼 |
| `--red` | `#D5092B` | 활성 표시·보조 화살표·키보드 초점 |
| `--rose-soft` | `#FFD7DE` | 헤더 문의 버튼 바탕, 기존 하단 문의 영역 보조 글자 |
| `--rose-hover` | `#F9C6CB` | 문의 버튼 호버, 텍스트 선택 배경 |
| `--surface` | `#FFFFFF` | 기본 바탕·대화상자 |
| `--peach` | `#F4EBE4` | 자산관리 설명 면 |
| `--surface-sage` | `#EAF0ED` | 공간·사람 설명 면 |
| `--surface-blue` | `#E9EFF2` | 기술 설명 면 |
| `--surface-cool` | `#EDF1F2` | 선택 항목·참고 결과 영역 |
| `--muted` | `#5C686C` | 보조 설명 |
| `--line` | `#DCE1E2` | 구분선·테두리·헤더 호버·펼침 밑줄 |
| `--red-section` | `#D2082B` | 하단 문의 영역 |

`#FFD7DE`는 복사 전부터 존재한 색이다. 헤더 문의 버튼에 이 색을 재사용했고, 글자는 Ink를 유지한다. `#F9C6CB`도 기존 선택 배경색을 재사용한 호버 색이다. 진한 브랜드 빨강을 경고·완료 같은 서비스 상태의 유일한 근거로 쓰지 않는다.

## 4. 글자

- 서체: Pretendard Variable → Pretendard → 시스템 서체.
- 휴대폰의 PC 버전 보기에서는 1280px 기준 화면을 통째로 축소해 메뉴·로고·여백의 비율을 유지한다. `jll-remix-viewport.js`가 작은 터치 화면의 넓은 뷰포트를 판별하며, `?layout=desktop`은 동일한 동작을 명시적으로 선택한다. `?layout=responsive`는 일반 반응형 배치로 돌아간다. 일반 PC 창과 기본 모바일 보기에는 이 축소를 적용하지 않는다.
- PC 보기의 기준 폭은 정보 배치용 캔버스이며 메뉴 15px 등 저장된 파운데이션 값은 유지한다. 좁은 화면용 규칙에는 `:where(html:not([data-sps-desktop]))` 조건을 두어 PC 캔버스에 중간 폭·모바일 배치가 섞이지 않게 한다. 뷰포트 단위는 `--sps-vw`·`--sps-vh`를 통해 캔버스와 함께 움직인다. 이 값은 기기별 표시 비율이며 편집용 디자인 토큰과 별도로 계산한다.
- 글자만 별도로 확대되는 현상은 공통 파운데이션의 `text-size-adjust: 100%`와 WebKit 접두사 속성으로 제한한다. 사용자 확대·축소 제한은 추가하지 않는다.
- 기본 본문: 16px / 줄높이 1.65 / 굵기 450. 실제 기존 섹션에는 12–15px 본문도 있다. 이를 모두 16px로 수정한 상태는 아니다.
- 제목 굵기: 500. 기본 제목 자간 -0.04em. 히어로는 아래 별도 값 적용.
- 영문 라벨: 11px / 1.5 / 650 / 자간 0.09em. 섹션별 작은 예외가 존재한다.

| 대표 요소 | 1280px 기준 | 390px 기준 |
|---|---|---|
| 히어로 H1 | 59px / 1.23 / 자간 -0.045em | 39px / 1.28 / 자간 -0.055em |
| 설명 섹션 H2 (`.editorial-copy h2`) | 43px / 1.3 | 35px / 1.3 |
| 인사이트 제목 H3 | 24px / 1.4 | 24px / 1.4 |
| 기본 본문 | 16px / 1.65 | 16px / 1.65 |
| 기본 라벨 `.eyebrow` | 11px / 1.5 | 9px / 1.5 |
| 문의 버튼 | 13px | 13px |

히어로는 1600px 이상 69px, 1100px 이하 54px, 850px 이하 51px, 600px 이하 39px, 360px 이하 34px다. 위 표는 전체 제목을 같은 크기로 바꾼 규칙이 아니라 대표 요소를 실제 CSS에서 정리한 것이다. 새로 넣는 비용·제약·오류·기한은 작은 장식 라벨을 복사하지 말고 충분한 본문 크기와 대비로 보여준다.

## 5. 레이아웃·간격·모양

- 본문 최대 폭: 1320px. 기본 좌우 72px, 1100px 이하 48px, 850px 이하 32px, 600px 이하 20px.
- 데스크톱 헤더: 상단 87px + 메뉴 49px. 850px 이하 상단 77px, 600px 이하 상단 75px·메뉴 펼침 방식.
- 히어로 기본 높이 720px. 넓은 화면 800px, 모바일 700px 등 기존 반응형 예외를 유지한다.
- 서비스 설명: 사진·설명 1:1. 모바일에서는 사진 다음에 설명을 놓는다. 인사이트는 데스크톱 3열, 모바일 1열이다.
- 대표 간격: 8, 16, 24, 40, 64, 88px. 기존 값의 예시이며 모든 간격이 이 목록만으로 구성되지는 않는다.
- 버튼 모서리 3px, 히어로 스토리 패널·대화상자 4px. 원형 아이콘이나 큰 곡면을 가져올 경우 쓰임과 영향을 별도로 검토한다.
- 로고는 `assets/logo.svg`, 비율과 색을 보존한다. 기본 너비 120px, 700px 이하 105px.

이번에 검색 버튼뿐 아니라 검색 대화상자와 관련 동작을 H에서 제거했다. 국가·언어 표시는 헤더에서 제거했다. 하단의 ‘대한민국 · 한국어’는 설정 기능이 아닌 기존 텍스트다. 모바일에도 문의 링크를 표시한다.

H 메인의 현재 진단은 일반적인 참고 가이드를 생성하는 로컬 화면이다. G의 상담 입력·접수 흐름을 가져온 상태가 아니다. 디자인 시스템의 버튼·선택·대화상자도 화면 예시이며 실제 업무나 상담을 실행하지 않는다.

## 7. 사진·움직임

- 기존 `assets/jll/`와 `assets/landing/`의 도시·외관·업무 공간 사진을 사용한다. 실제 관리 실적의 증거로 설명하지 않는다.
- 히어로: 넓은 사진 위 어두운 그라데이션 + 흰 글자. 사진의 시야를 가리지 않도록 문장 폭을 제한한다.
- 사진 크로스페이드: 950ms. 히어로 제목 줄별 등장: 850ms, 시작 지연 80ms + 줄당 90ms.
- 스토리 진행 주기: 7200ms. 사진 확대 효과 8500ms는 별도 값이다. 일시정지 버튼을 유지한다.
- 스크롤 등장: 28px → 0, 800ms. 모바일 18px, 650ms. 사진 마스크 전환 1100ms.
- 주 이징: `cubic-bezier(.22,1,.36,1)`. 스크롤은 브라우저의 기본 스크롤을 사용한다.
- 움직임 감소 설정에서는 자동 재생·장식 이동을 줄이고, 글·버튼·정보는 그대로 읽을 수 있게 한다.
- 시각화 페이지의 재생 예시는 데스크톱 스크롤 등장 한 가지다. 전체 히어로 모션 엔진을 복제한 것은 아니다.

## 8. 재조합 판단

다른 시안을 가져올 때는 다음 순서로 확인한다.

1. 같은 역할의 글자·버튼·간격을 H 기준에 맞춘다.
2. 행동의 목적과 이동할 곳을 연결하고, 닫기·뒤로 가기 후 흐름을 확인한다.
3. 상태·금액·조건·근거가 모션이나 옅은 색에 가려지지 않는지 확인한다.
4. 새 기능이나 서비스 제공을 암시하는 문구는 실제 제공 범위와 대조한다.
5. H와 원본 B는 별도 경로로 비교한다. 첫 문구·사진·콘텐츠 차이를 디자인 효과로 오인하지 않는다.

색상 값은 토큰 파일에서 관리하고 문서·시각화의 설명은 그 역할을 기록한다. 컴포넌트 예시는 메인 CSS를 재사용한다. 시각화 페이지 자체의 사이드바·타이포 견본·격자는 문서 탐색을 위한 별도 레이아웃으로, 제품의 새 컴포넌트라고 간주하지 않는다.

| 이전 | 현재 | 이유·영향 |
|---|---|---|
| 검색·국가/언어 표시가 있는 H 헤더 | 문의·메뉴 중심의 헤더 | 사용자 선택. 검색 기능과 그에 연결된 코드 제거 |
| 회청색 문의 버튼 | 기존 Soft Rose 바탕·Rose Hover | 기존 색상을 사용해 문의 입구를 강조 |
| 모바일에서 문의 버튼 숨김 | 로고·문의·메뉴 표시 | 검색 제거 후 확보한 공간에서 같은 문의 행동 제공 |
| H 전용 문서 없음 | 이 문서와 시각화 페이지 추가 | 재조합 기준을 실제 화면과 함께 확인 |

최초 Mastercard 문서는 수정하지 않았다. H는 이미 JLL 기반 별도 시안이므로 이번 기준은 H 적용본에만 해당한다. 실제 고객이 더 잘 이해하거나 상담을 더 많이 신청하는지는 이 작업으로 검증하지 않았다.

## 10. 최초 시각화 실행 확인 (Edition 01)

- 데스크톱에서 헤더 검색·국가/언어 요소가 없고 문의 버튼이 `rgb(255, 215, 222)`, 글자가 `rgb(16, 37, 43)`인 것을 확인했다. 버튼 색과 글자색의 계산 대비는 12.13:1이다. 이는 이 색 조합의 계산값이며 전체 사이트 접근성 인증을 뜻하지 않는다.
- 문의 링크 → 하단 참고 진단 → 대화상자 열기·닫기를 확인했다. 검색 코드 제거 후 기존 진단 진입이 동작했다.
- 모바일 390×844에서 문의 링크·메뉴 표시와 메뉴 펼침·닫힘, 확인한 메인·시각화 화면의 가로 넘침 없음을 확인했다.
- 시각화에서 Soft Rose 값 복사, 39px 모바일 타이포 전환, 대화상자 닫기 후 버튼 초점 복귀, 선택값 변경, FAQ 펼침, 모션 재생을 확인했다. 최종 시각화 탭의 오류·경고 로그는 없었다.
- 수정한 스크립트 구문 검사와 로컬 문서·파일 참조 확인을 통과했다. B와 기존 공통 원본 파일들의 SHA-256은 작업 전 기록과 일치한다.
- 움직임 감소 설정의 분기 코드는 유지·구현되어 있으나 이번 브라우저에서 OS 설정을 바꿔 실행하지는 않았다. 모든 화면·브라우저·접근성 항목을 검증한 것은 아니다.

## 11. 시각적 설계 문서 (Edition 02)

사용자 요청에 따라 기존 시각화 경로를 파운데이션과 컴포넌트를 탐색하는 문서로 확장했다. 실제 H 메인·토큰은 변경하지 않았다. 섹션별로 식별자, 시각 견본, 치수·구조, 행동과 적용 기준을 함께 배치한다.

컴포넌트는 메인 CSS를 가져온다. 문서 안에서는 큰 섹션·카드·헤더를 담기 위해 일부 치수와 여백을 조정하며 해당 견본에 이를 설명한다. 주석 번호·측정선·목차·축소 부품 아이콘은 문서용 표현이다. 제품용 토큰이나 새 업무 기능으로 취급하지 않는다.

- 그리드 도식의 6칸은 2분할·3열의 정렬 관계를 설명한다. 실제 제품에 6열 그리드를 도입한 것이 아니다.
- 스토리 견본은 수동 전환만 사용한다. 메인의 4개 스토리·자동 전환·일시정지 엔진을 복제하지 않았다.
- 상세 대화상자의 본문은 컴포넌트 작동을 설명하는 문서 콘텐츠다. 실제 상담·보고·관리 실행을 제공하지 않는다.
- 원본에 없는 로딩·전송 오류·비활성 상태는 현재 구현된 컴포넌트로 추가하지 않았다.
- 모바일에서 데스크톱 타이포 크기를 선택하면 견본 영역 안에서 가로로 살펴볼 수 있다. 페이지 자체는 가로 스크롤되지 않도록 한다.

색·치수의 실제 기준은 위 3–7절과 토큰·메인 CSS에 있다. Edition 02는 기준을 시각적으로 풀어 보여주는 확장이며 브랜드·서비스·컨셉을 변경하는 단계가 아니다.

### Edition 02 실행 확인

- 1280px 기본 화면과 390×844 모바일 화면에서 페이지 가로 넘침이 없었다. 모바일에서 데스크톱 타이포를 선택했을 때 견본 안에만 가로 스크롤이 생겼다.
- Soft Rose 복사, 39px 글자 크기 전환, 헤더 견본 메뉴 선택, 세 번째 스토리의 사진·제목·번호 변경을 확인했다.
- 공간 이야기 필터 → 해당 카드 상세 열기 → Escape 닫기를 실행했다. 공간 이야기 필터, 보이는 카드 1개, 원래 이미지 버튼의 초점이 유지됐다.
- 건물 유형 변경, FAQ 펼침, 800ms 모션 재생을 확인했다. 확인한 탭의 오류·경고는 없었다.
- 스크립트 구문 검사, HTML 중복 ID·내부 앵커·로컬 참조 파일 검사를 통과했다.
- 실제 신청·저장·전송은 없고, OS의 움직임 감소 설정이나 모든 브라우저를 검증한 결과는 아니다. 인쇄용 스타일은 제공하지만 인쇄 결과를 별도로 검수하지 않았다.

## 12. 문서에서 사이트로 연결되는 편집 (Edition 03)

파운데이션·컴포넌트의 각 섹션에 **값 조정**을 추가했다. 편집 범위는 H 메인과 이 시각화 문서, H 소개의 공통 헤더다. B·C·G 등 다른 시안과 H 소개의 본문에는 적용하지 않는다.

- 색상 12개, 로고 너비, 제목·기본 본문 크기, 본문 폭·좌우 여백·카드 간격, 모서리, 스크롤 등장 시간·거리와 컴포넌트별 주요 치수를 편집한다.
- 버튼·헤더·스토리 항목·서비스 설명·카드·입력·FAQ·대화상자에 해당하는 컨트롤이 있다. 기존 견본의 클릭·선택은 기능 시연이고 **값 조정**의 입력이 사이트 디자인을 바꾼다.
- 입력값은 견본과 같은 출처의 열린 H 탭에 즉시 반영되고, 마지막 입력 후 약 450ms에 프로젝트 설정 파일로 저장된다. 다른 로컬 출처의 탭은 저장 알림 후 갱신된다.
- 현재 로컬 환경의 저장 파일은 `design/jll-remix/theme.json`이다. 기본값과 다른 항목만 저장한다. 서버 재시작·새로고침에도 유지되며 브라우저 저장소에만 의존하지 않는다.
- 항목별 **기본값**과 **전체 기본값 복원**으로 오버라이드를 제거한다. 원본 B·최초 디자인 문서와 H 기본 스타일은 기준으로 보존된다.
- 범위를 벗어난 수치와 잘못된 HEX 색상은 저장하지 않는다. 저장 실패 시 **미저장** 상태와 다시 시도 버튼을 표시하고 입력값을 유지한다. 연결이 돌아오면 재시도한다.
- 저장 기능 없이 정적 미리보기만 실행해도 마지막으로 저장한 JSON 설정은 읽어 적용한다. 새 편집을 저장하려면 디자인 저장 서버가 실행되어 있어야 한다.
- 편집기 입력은 기준값이다. 별도 모바일 항목과 기존 반응형 기본 규격을 구분한다. 문서의 고정 설명 수치는 초기 규격이며 색상·타이포·대표 치수 표시와 실제 견본은 편집값에 맞춰 갱신한다.
- 변경값이 같은 컴포넌트의 모든 사용처에 적용되므로 색상 대비와 좁은 화면에서의 조합은 확인해야 한다. 구조·서비스 문구·실제 신청 기능을 편집하는 도구는 아니다.

### 실행·파일 관계

`npm run dev` 또는 `npm start`로 로컬 미리보기와 디자인 저장 서버를 실행한다. 기존 3000 미리보기가 실행 중이면 유지하고, 디자인 저장은 127.0.0.1:3001에서 제공한다. 모두 로컬 루프백에만 바인딩한다.

| 파일 | 역할 |
|---|---|
| `jll-remix-tokens.css`·기존 H CSS | 초기 표현과 반응형 기본값 |
| `jll-remix-theme-schema.js` | 편집 가능 항목·기준값·허용 범위의 공유 정의 |
| `design/jll-remix/theme.json` | 실제 저장된 H 편집값·저장 시각·수정 번호 |
| `jll-remix-theme.css` | H 및 문서 견본에서 편집 토큰을 사용하는 연결 |
| `jll-remix-theme.js` | 저장값 적용·실시간 동기화·재연결 |
| `jll-remix-theme-editor.js`·`.css` | 문서 안의 편집기·저장 상태·복원 |
| `scripts/design-server.cjs` | 제한된 스타일 값의 원자적 저장·변경 알림·로컬 미리보기 |
| `scripts/design-server.test.cjs` | 저장·유효성·동시 변경·복원·출처 제한 검사 |

정보 우선순위의 판단은 여전히 CONCEPT.md를 따른다. 이 편집 기능이 컨셉이나 서비스 약속을 자동으로 변경하지 않는다.

### 확인한 결과

- 문의 버튼 색·최소 높이, 히어로 제목 크기, 스토리 선택 배경을 문서에서 변경하고 열린 H 탭에서 같은 값이 적용되는 것을 확인했다.
- 변경한 값이 JSON 파일에 저장되고 H 새로고침 후에도 유지되는 것을 확인했다. 테스트 편집은 원래 값으로 복원했다.
- 잘못된 색상 입력은 오류를 표시하고 적용하지 않았다.
- 서버 검사는 허용 항목·수치 범위·색상 형식, 동시 변경의 보존, 파일 저장·항목 삭제·전체 복원, 외부 출처 쓰기 차단, 정적 파일 부분 응답을 확인했다.
- 문서의 14개 편집 영역·47개 값 조절을 확인했다. 기본 1280px와 모바일 390px에서 문서의 가로 넘침이 없었고, 항목별 모서리 복원도 실행했다.

## 13. 메인·SPS 소개 공통 헤더 (2026-10-06)

- `jll-remix-header.js`가 H 메인과 H 소개의 로고·문의 버튼·메뉴·햄버거 메뉴를 한 곳에서 생성한다. `jll-remix-header.css`가 두 페이지의 헤더 표현과 반응형 규격을 관리한다. 페이지에는 `data-sps-header` 자리만 두며 별도 소개 헤더를 작성하지 않는다.
- 기존 메인의 흰색 두 줄 구성과 Soft Rose 문의 버튼을 유지한다. 소개의 햄버거 기능을 공통 헤더에 연결해 두 페이지에서 사용하며, 스크롤 중에도 헤더를 유지한다. 소개에서 SPS 소개 메뉴는 현재 페이지로 표시한다.
- 소개의 전역 메뉴는 메인의 같은 목적지로 연결한다. 예를 들어 서비스는 `jll-remix.html#services`로 이동한다. 소개 안의 비전·관점·공간 탐색 링크는 본문과 푸터에 유지한다.
- 헤더 높이를 측정해 앵커 이동 여백과 소개의 관점 선택 영역에 반영한다. 데스크톱 소개 히어로는 헤더를 제외한 화면 높이에 맞춰 첫 제목이 잘리지 않게 한다. 햄버거 메뉴가 열리면 배경 조작을 막고, Escape로 닫으면 버튼으로 초점을 돌린다.
- 디자인 설정은 메인에서는 전체 화면에, 소개에서는 공통 헤더에만 적용한다. 소개 본문의 글자·색·이미지·모션은 자체 기준을 유지한다. 최초 디자인 원본과 다른 시안에는 변경을 전파하지 않는다.

확인: 데스크톱 메인→소개 이동에서 헤더·로고·문의 버튼·메뉴의 크기, 글꼴, 색이 일치했다. 390×844에서 메뉴 열기·서비스 이동·소개 복귀, 가로 넘침 없음, Escape 닫기를 확인했다. 헤더 상단 높이 87→90px 편집이 메인과 소개에 반영됐으며 기본값으로 복원했다.

### 로고로 메인에 돌아올 때의 전환 (2026-10-06)

- H 메인·소개는 문서 간 전환을 공유한다. 이전 화면을 유지하다 새 화면으로 불투명하게 교체하며, 본문·헤더에 투명도 전환을 넣지 않는다. 재점검에서 간헐적인 밝기 변화를 줄이기 위해 기존 180ms 겹침 효과를 제거했다. 공통 헤더는 별도 전환 영역을 유지한다.
- 헤더·테마·첫 화면 모션 스크립트에 `blocking="render"`를 지정해 빈 헤더나 초기화 전 화면을 먼저 그리지 않게 한다. H 메인·소개 사이 링크에 포인터/초점이 닿으면 도착할 첫 이미지를 준비하고, 클릭 시 해석이 끝나지 않았다면 현재 화면에서 최대 800ms 기다린다. 이미지 오류·지연이 이동을 무기한 막지 않게 한다.
- 확정 저장된 디자인 값은 같은 탭의 세션에 보관해 이동 후 첫 렌더부터 적용한다. 파일/API를 다시 읽어 최신값으로 갱신하며, 저장 전 편집값은 이 캐시에 넣지 않는다. 캐시가 없거나 저장소를 사용할 수 없는 첫 방문은 기본값을 그린 뒤 저장값을 읽는 기존 대체 동작을 유지한다.
- 소개에서 메인으로 돌아오면 첫 제목·설명·CTA를 숨기는 진입 애니메이션을 반복하지 않는다. 메인 첫 방문의 진입 효과와 이후 스토리 전환은 유지한다.
- 이동은 일반 링크 방식이다. 전환을 지원하지 않는 브라우저는 일반 문서 이동을 사용하며, 움직임 감소 설정에서는 전환 시간을 줄인다. 기반 API: [Chrome 문서 간 화면 전환](https://developer.chrome.com/docs/web-platform/view-transitions/cross-document).
- 재수정 전, 소개→메인 복귀 직후 문의 버튼이 분홍색을 먼저 그리고 저장된 회색으로 바뀌는 장면을 직접 확인했다. 수정 후 데스크톱 3회 왕복, 뒤로/앞으로 이동, 390px 모바일 메뉴→소개→로고 복귀에서 문의 색 `#e9eef0`, 준비된 첫 이미지, 제목 불투명도 1, 헤더 1개, 가로 넘침 없음을 확인했다. 콘솔 경고·오류는 없었다. 모든 브라우저나 저속 네트워크에서 확인한 결과는 아니다.

### 서비스 화살표 회전과 닫기 유예 (2026-10-07)

- 마우스가 버튼·패널 영역 밖으로 나가면 기존 180ms 대신 650ms 후 닫는다. 유예 중 다시 진입하면 예약을 취소해 메뉴를 유지한다. Escape, 바깥 클릭, 항목 선택은 즉시 닫는다. 모바일은 클릭으로 열고 닫는다.
- V1·V2·V3 메인·소개와 디자인 시스템 견본이 같은 컴포넌트를 사용한다.

- 닫히는 동안 메뉴 내용은 초점·클릭 대상에서 제외한다. 움직임 감소 설정에서는 즉시 표시/숨김한다. 공통 컴포넌트를 사용하는 V1·V2·V3와 소개·디자인 시스템 견본에 적용한다.
- 확인: 실제 브라우저에서 닫기 직후 패널은 표시된 채 투명도 약 0.88로 감소하고, 종료 후 hidden 상태가 됐다. 닫힘 중 다시 열기에서는 중간 투명도에서 이어지고 메뉴의 초점·클릭 가능 상태가 복원되는 것을 확인했다.

### V1·V4 서비스 안내 블록 상단 정렬 (2026-10-07)

> 아래 변경은 후속 요청으로 철회했다. 현재 기준은 다음 ‘질문·제목 정렬 복원과 상단 여백 축소’ 항목이다.

- 넓은 PC 메뉴의 정렬 기준을 질문 첫 줄에서 빨간 SERVICES 라벨의 상단으로 변경한다. SERVICES와 부동산 자산관리·임대 마케팅·실내건축 제목이 같은 높이에서 시작하며, “어떤 서비스가 필요하세요?”는 라벨 아래 12px 간격으로 배치한다.
- 라벨을 위로 띄우는 절대 위치를 제거하고 공통 그리드의 상단 정렬을 따른다. 메인·소개·컴포넌트 견본이 같은 규칙을 사용한다. 좁은 화면에서 안내가 별도 행이 되는 구성과 모바일 라벨 숨김은 유지한다.

### V1·V4 질문·제목 정렬 복원과 상단 여백 축소 (2026-10-07)

- 사용자는 이전 질문·제목 정렬을 선호하며 실제 불편은 부동산 자산관리 제목 위의 넓은 여백이라고 설명했다. 넓은 PC 메뉴에서 “어떤 서비스가 필요하세요?” 첫 줄과 세 서비스 제목의 상단·줄높이를 다시 일치시킨다. 빨간 SERVICES는 질문 위 12px 간격의 보조 라벨로 복원한다.
- 공통 컴포넌트의 콘텐츠 상단 padding을 56px에서 40px로 줄인다. 하단 40px와 서비스 항목 최소 높이 216px는 유지해 픽토그램 영역을 압축하지 않는다. 메인·소개 및 V1 레이아웃을 공유하는 V4에 함께 적용한다.
- 1100px 이하와 컴포넌트 견본에서는 라벨을 일반 흐름에 배치한다. 850px 이하의 상하 28px와 모바일 메뉴의 8px/18px 여백은 유지한다.

### 서비스 메뉴 강조와 현재 위치·조작 상태 구분 (2026-10-07)

- V1·V4 공통 서브메뉴에서 SERVICES 영문 라벨을 제거한다. 왼쪽 “어떤 서비스가 필요하세요?”와 세 서비스의 방향 화살표에 기존 Red 토큰을 사용한다. 제목은 Ink, 설명은 Muted를 유지하고 호버·키보드 초점에서 해당 제목만 Red로 바뀐다. 기존 화살표 이동 모션과 픽토그램의 작은 붉은 포인트를 유지하며 새 배경이나 배지는 추가하지 않는다.
- 질문 첫 줄과 서비스 제목의 상단·줄높이, PC 상단 여백 40px를 유지한다. 라벨 제거로 생기는 별도의 빈 줄은 두지 않는다. V2·V3 비교용 메뉴 콘텐츠는 보존한다.
- 공통 헤더에서 현재 페이지·현재 섹션은 Muted(#5C686C 기본값)의 3px 선, 호버·키보드 초점·서비스 펼침은 Red(#D5092B 기본값)의 3px 선으로 구분한다. 소개 페이지에서 서비스를 펼치면 소개의 회색 선과 서비스의 빨간 선이 함께 표시된다. 현재 메뉴 자체에 호버·초점을 주면 조작 상태인 빨강이 우선한다.
- 모바일은 밑줄을 추가하지 않고 현재 항목과 조작 항목의 텍스트에 같은 색상 규칙을 적용한다. 현재 위치의 aria-current와 서비스 버튼의 aria-expanded는 유지한다. 디자인 시스템의 헤더 견본에도 동일한 색상 구분을 적용한다.

### 현재 위치의 연한 회색과 서비스 묶음 간격 (2026-10-07)

- 현재 페이지·현재 섹션의 데스크톱 밑줄을 Muted에서 기존 Line 토큰(--line, 기본 #DCE1E2)으로 바꾼다. 새 회색을 만들지 않으며 파운데이션 → 색상 → 구분선에서 함께 조절된다. 호버·초점·펼침의 Red와 모바일 텍스트의 읽을 수 있는 Muted는 유지한다. 컴포넌트 견본의 현재 위치 선도 Line을 공유한다.
- V1·V4의 넓은 PC 서브메뉴에서 질문과 서비스 목록 사이 가로 간격을 28px에서 64px로 넓힌다. 전체 콘텐츠 폭과 기존 안내/목록의 비율은 유지하고 목록 안의 세 칸은 동일한 너비를 유지한다. 현재 확인한 콘텐츠 폭 1086.4px에서 질문 영역 176.4→170.4px, 서비스 칸 각각 294→284px가 되도록 간격에 공간을 배분한다.
- 관련된 세 서비스 사이의 22px 안쪽 여백보다 안내와 목록의 간격을 크게 두어 두 묶음을 구분한다. 제목 높이와 상하 40px 여백, 픽토그램 크기는 유지한다. 1100px 이하에서는 기존 1열 안내와 28px 행 간격, 모바일 메뉴에서는 기존 16px 행 간격을 사용한다.

### 현재 가능한 범위

성함·연락처·문의 내용은 필수이며, 주제와 건물 위치는 선택이다. 연락 방식은 전화 또는 이메일 하나를 선택한다. 오류는 요약과 해당 입력란에 표시하고 수정할 수 있다. 내용 확인 → 수정 → 복사가 가능하다. 닫기·Escape 이후 입력과 단계는 같은 문서에서 유지되고 초점은 실행한 버튼으로 돌아간다. 초기화에는 확인 단계를 둔다.

서버 전송, 데이터베이스 저장, 담당자 알림, 접수번호 생성은 없다. 문의 정보는 현재 문서의 메모리에만 있으며 URL·브라우저 저장소·로그로 보내지 않는다. 새로고침·페이지 이동 시 사라진다. 실제 접수 완료를 표시하지 않고, 작성 화면과 확인 화면 모두 전송 전 상태를 안내한다. 전화 링크는 사용자가 직접 통화 앱에서 진행한다.

## 2026-10-08 · 소개 히어로의 스크롤 여백

- H 소개 공통 화면(V1–V4)의 이미지 외곽은 스크롤 위치와 무관하게 전체 폭을 유지한다. 스크롤 중 좌우를 최대 3%씩 잘라내던 효과와 첫 진입의 가로 잘림을 제거했다.
- 배경 전체에 적용하던 세로 이동을 사진에만 적용한다. 제목과 아래 방향 버튼은 히어로 하단을 기준으로 유지하고, 사진의 이동·확대와 기존 페이드·제목 등장 효과는 유지한다.
- 제목 아래 간격은 기존 반응형 값인 화면 높이의 6.2%, 모바일 72px를 사용한다. 시작 간격을 늘리기보다 스크롤 중 그 간격을 잃지 않도록 고쳤다. 새 색이나 공통 파운데이션 값은 추가하지 않았다.
- 직접 확인: 1294×874 화면에서 시작과 약 420px 스크롤 후 모두 제목 아래 약 54px, 390×844 화면에서 시작과 약 211px 스크롤 후 모두 72px를 유지했다. 이미지 외곽 가로 잘림은 없었다. 기존 화면에서는 약 450px 스크롤 시 제목이 히어로 하단을 약 7px 넘어가는 현상을 확인했다.


### 같은 날 · 첫 진입·새로고침의 높이 변경 제거

히어로 컨테이너의 `height`와 `clip-path`를 바꾸던 진입 애니메이션을 제거했다. 컨테이너 높이는 반응형 CSS에서만 정하고 사진·문구의 내부 변환만 애니메이션한다. 초기 측정 높이와 헤더 정착 후 높이가 달라져 효과 종료 시 튀는 동작을 만들지 않는다. H 소개 V1–V4에 같은 스크립트를 적용한다. 1294×874 화면의 새로고침과 메인 → 소개 이동에서 진입 중·효과 완료 후 높이가 모두 약 737.4px로 유지되는 것을 확인했다.


### 2026-10-08 · 헤더 현재 위치와 호버의 색상 역할 교체

사용자 요청에 따라 이전의 회색 현재 위치 / 빨강 호버 규칙을 교체한다. PC의 현재 페이지·현재 섹션 밑줄은 파운데이션 `--red`, 호버·키보드 초점·서비스 펼침 밑줄은 기존 `--line`을 사용한다. 두 상태가 겹치면 현재 위치의 빨강이 우선한다. 모바일 펼침 메뉴는 현재 항목의 텍스트를 `--red`, 탐색·펼침 텍스트를 가독성이 확보된 기존 `--muted`로 표시한다. 키보드 초점 외곽선은 유지한다.

새 색상이나 별도 값은 만들지 않았다. 파운데이션 색상 편집기의 이름을 **강조·초점·현재 메뉴 / Red**, **구분선·헤더 호버**로 명확히 했다. 기존 값 변경은 해당 색상을 공유하는 다른 요소에도 반영된다. H 공통 헤더, 서비스 버튼, V1–V4와 디자인 시스템 견본에 적용하며 서비스 카드 내부의 빨간 포인트는 유지한다.

직접 확인: 소개 활성 밑줄 Red(RGB 213,9,43) + 펼친 서비스 밑줄 Line(RGB 220,225,226), 현재 서비스에서 펼쳐도 Red 유지, 컴포넌트 견본의 같은 두 상태, 모바일 현재 항목 Red + 펼친 서비스 Muted(RGB 92,104,108)를 확인했다.
